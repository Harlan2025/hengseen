# 衡简叙约 核心接口清单 V1.4

配套文档：衡简叙约 访谈式智能合同生成系统 PRD V1.4
接口风格：RESTful JSON
统一前缀：/api/v1
认证方式：Bearer Token（Supabase JWT）
统一返回格式：
```json
{
  "code": 0,
  "msg": "提示信息",
  "data": {}
}
```

## 一、认证模块（V1.4修订）

### 1.1 用户注册
- **接口**：`POST /api/v1/auth/register`
- **描述**：手机号注册
- **请求体**：
```json
{
  "phone": "13800138000",
  "code": "123456",
  "nickname": "张三",
  "agree_user_agreement": true,
  "agree_privacy_policy": true,
  "agreement_version": "V1.0"
}
```
- **注意**：
  - `agree_user_agreement` 和 `agree_privacy_policy` 必须为 `true`
  - `agreement_version` 为当前协议版本号
  - 未勾选或版本不一致时返回错误码 7001

- **响应**：
```json
{
  "code": 0,
  "data": {
    "user_id": "uuid",
    "access_token": "jwt_token",
    "refresh_token": "refresh_token"
  }
}
```

### 1.2 用户登录
- **接口**：`POST /api/v1/auth/login`
- **描述**：手机号+验证码登录
- **请求体**：
```json
{
  "phone": "13800138000",
  "code": "123456",
  "agree_user_agreement": true,
  "agree_privacy_policy": true,
  "agreement_version": "V1.0"
}
```
- **注意**：
  - 登录时若协议版本已更新，需重新勾选同意
  - 未勾选或版本不一致时返回错误码 7002

- **响应**：同注册接口

### 1.3 微信授权登录（小程序/App）
- **接口**：`POST /api/v1/auth/wechat`
- **描述**：微信一键登录
- **请求体**：
```json
{
  "code": "wechat_auth_code",
  "platform": "wechat_miniapp",
  "agree_user_agreement": true,
  "agree_privacy_policy": true,
  "agreement_version": "V1.0"
}
```

- **响应**：同注册接口

### 1.4 刷新Token
- **接口**：`POST /api/v1/auth/refresh`
- **描述**：使用refresh_token换取新access_token
- **请求体**：
```json
{
  "refresh_token": "token_string"
}
```

### 1.5 退出登录
- **接口**：`POST /api/v1/auth/logout`
- **描述**：使当前token失效
- **请求头**：Authorization: Bearer {token}

### 1.6 获取当前用户信息
- **接口**：`GET /api/v1/auth/me`
- **描述**：获取当前登录用户详细信息
- **响应**：
```json
{
  "code": 0,
  "data": {
    "user_id": "uuid",
    "nickname": "张三",
    "avatar_url": "https://...",
    "login_type": "phone",
    "created_at": "2026-08-16T10:00:00Z",
    "agreed_at": "2026-08-16T10:00:00Z",
    "agreement_version": "V1.0"
  }
}
```

### 1.7 获取当前协议内容（V1.4新增）
- **接口**：`GET /api/v1/agreements`
- **描述**：获取当前生效的用户协议和隐私政策内容。**此接口应在登录表单加载前调用**，前端通过比较上次同意的协议版本（localStorage缓存）与返回的当前版本，决定是否显示重新同意提示。
- **响应**：
```json
{
  "code": 0,
  "data": {
    "user_agreement": {
      "agreement_id": "uuid",
      "agreement_type": "user_agreement",
      "title": "用户协议",
      "content": "欢迎使用衡简叙约...\n\n一、协议范围\n...",
      "version": "V1.0",
      "is_active": true,
      "updated_at": "2026-08-16T10:00:00Z"
    },
    "privacy_policy": {
      "agreement_id": "uuid",
      "agreement_type": "privacy_policy",
      "title": "隐私政策",
      "content": "我们重视您的隐私...\n\n一、信息收集\n...",
      "version": "V1.0",
      "is_active": true,
      "updated_at": "2026-08-16T10:00:00Z"
    }
  }
}
```

### 1.8 获取用户协议同意记录（V1.4新增）
- **接口**：`GET /api/v1/auth/agreement-consent`
- **描述**：获取当前用户的协议同意记录
- **响应**：
```json
{
  "code": 0,
  "data": {
    "user_agreement": {
      "version": "V1.0",
      "agreed_at": "2026-08-16T10:00:00Z"
    },
    "privacy_policy": {
      "version": "V1.0",
      "agreed_at": "2026-08-16T10:00:00Z"
    },
    "needs_reagree": false
  }
}
```
- **注意**：若协议版本已更新，`needs_reagree` 为 `true`，提示用户重新同意

- **接口**：`POST /api/v1/admin/agreements`
- **描述**：创建新的协议版本（仅Admin可访问）

```json
    "agreement_id": "uuid",
    "version": "V1.1",
    "is_active": true
  }
}
```
- **注意**：新协议创建后会自动激活，旧版本自动设为 inactive

## 十六、前端交互规范（V1.4新增）

### 16.1 注册/登录页面协议勾选

**组件规范：**
```html
<div class="agreement-checkbox">
  <input type="checkbox" id="agree_user_agreement" v-model:checked="form.agree_user_agreement" />
  <label for="agree_user_agreement">
    我已阅读并同意
    <a href="#" @click="showAgreement('user_agreement')">《用户协议》</a>
    和
    <a href="#" @click="showAgreement('privacy_policy')">《隐私政策》</a>
  </label>
</div>
<button :disabled="!form.agree_user_agreement || !form.agree_privacy_policy" @click="handleRegister">
  立即注册
</button>
```

**交互规则：**
1. 两个复选框默认未勾选
2. 未全部勾选时，注册/登录按钮置灰
3. 点击「用户协议」或「隐私政策」链接，弹出模态框展示协议内容
4. 协议内容支持滚动查看
5. 弹窗内有「我知道了」按钮，点击关闭

### 16.2 协议弹窗展示

**弹窗规范：**
```html
<div class="agreement-modal" v-if="showModal">
  <div class="modal-content">
    <h3>{{ currentAgreement.title }}</h3>
    <div class="modal-body" v-html="currentAgreement.content"></div>
    <div class="modal-footer">
      <button @click="closeModal">我知道了</button>
    </div>
  </div>
</div>
```

### 16.3 协议版本更新提示

**场景：** 用户登录后，系统检测到协议版本已更新

**提示弹窗：**
```
┌─────────────────────────────────────┐
│     用户协议已更新                   │
│                                     │
│  我们更新了《用户协议》和《隐私政策》，│
│  请您重新阅读并同意。               │
│                                     │
│  [查看更新内容]  [不同意]            │
│                                     │
└─────────────────────────────────────┘
```

**处理逻辑：**
- 点击「查看更新内容」：打开协议详情弹窗
- 点击「不同意」：强制退出登录，提示「需要同意最新协议才能继续使用」
- 点击「我知道了」：记录同意，进入系统

### 16.4 协议内容样式

**富文本渲染规范：**
- 标题：字体加粗，字号16px
- 正文：字体14px，行高1.6
- 列表：有序/无序列表自动识别
- 链接：蓝色，下划线
- 段落间距：12px

### 17.2 协议版本管理

**版本命名规则：**
- 主版本：V1.0, V1.1, V1.2...
- 大版本：V2.0（重大修改）
- 小版本：V1.0.1（修复性更新，可选）

**版本状态：**
- `active`：当前生效版本
- `inactive`：历史版本

## 十八、安全注意事项（V1.4新增）

### 18.1 协议内容安全
- 协议内容经过富文本过滤，防止XSS攻击
- 管理员编辑协议需二次确认
- 协议修改记录审计日志

### 18.2 用户同意记录安全
- 同意记录加密存储
- 记录IP地址和设备信息
- 防止伪造同意记录

### 18.3 协议更新通知
- 协议更新后，已注册用户下一次登录时弹出重新同意提示（匿名用户仅显示横幅通知）
- 提供历史版本查看功能
- 用户可随时查看已同意的协议版本
