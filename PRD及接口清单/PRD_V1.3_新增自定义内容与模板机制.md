# 第一部分：产品PRD（修订版）

## 一、产品概述

### 1.1 品牌释义
**衡简叙约**
- 叙：以对话访谈方式，叙明完整交易事实（产品核心交互形态）
- 衡：权衡各方权责、识别交易风险、公允界定权利义务
- 简：简化合同起草流程，摆脱低效模板复制，降低文书制作门槛
- 约：商事合约、法律协议，对应产品最终产出物

品牌简称对外传播统一使用「衡简」，便于用户记忆；商标同步布局「衡简」「衡简叙约」双名称保护，规避商标淡化、竞品仿冒。

### 1.2 产品定位
区别于传统模板填空类合同工具，**衡简叙约**采用法务访谈建模机制：不依赖固定合同模板，通过多轮对话采集真实业务事实，动态生成法律文件框架，自动识别交易风险，最终输出定制化商事法律文书。
面向企业法务、经营者、商务人员，覆盖全部常见民商事协议场景。

### 1.3 核心差异化能力
1. 事实优先，动态生成框架，拒绝固化模板套用
2. 内置A‑J十大法律文件分类，支持【主类型+附属类型】混合复合文件
3. 标准化访谈流程，自动持续累积访谈记录表
4. 内置三条全局指令：`/重置` `/回溯` `/导出`
5. 云端轻量化架构，无需自建服务器
6. Web / APP / 微信小程序三端数据互通、账号统一
7. 匿名先用、付费后下载，降低使用门槛
8. 人工服务对接，专家一对一沟通
9. **用户自定义内容插入**（V1.3新增）
10. **后台动态定价与模板管理**（V1.3新增）

### 1.4 终端覆盖范围
1. Web网页端：完整版，面向PC办公场景，支持完整编辑、批量导出、项目管理
2. APP（iOS & Android）：移动端持续访谈、项目查看、消息提醒
3. 微信小程序：轻量化入口，支持临时快速创建项目，简易导出

### 1.5 整体技术架构
1. 边缘层：Cloudflare
    - 静态资源CDN托管、全站HTTPS、域名解析
    - 边缘路由、请求缓存、流量防护、跨域统一处理
    - 边缘预处理拦截斜杠指令请求
2. 云端底座：Supabase
    - 用户认证、账号体系
    - PostgreSQL结构化数据库持久化项目、会话、访谈数据
    - 对象存储：导出文档、附件资源
    - RLS行级权限，数据隔离；实时订阅实现多端同步
3. AI服务层：独立大模型推理服务
    - 负责访谈提问、文本解析、大纲生成、风险提炼、合同文本生成
    - **流程控制、状态机、访谈记录表统一由后端管控，AI不掌控业务流程**
    - 通过OpenAI兼容接口调用，支持多种大模型（DeepSeek、Qwen、GPT等）
4. 支付服务层：微信支付 + 支付宝
    - 统一下单、二维码生成、支付回调、订单查询
5. 管理后台层（V1.3新增）
    - 定价策略配置
    - 模板管理（合同模板、条款模板）
    - 专家审核管理
    - 数据统计分析
6. 前端层：三端独立实现，业务逻辑统一
    - Web：React/Vue3
    - APP：Flutter / UniApp跨端
    - 微信小程序：原生小程序

## 二、核心业务规则

### 2.1 十类标准文件分类（A‑J）
A：普通商事交易合同（买卖、服务、履约验收）
B：确认/意向类文件（备忘录、会议纪要、意向书）
C：资本类交易（股权转让、增资、资产收购、投融资）
D：合作类协议（框架合作、合资协议）
E：人事劳务类（劳动合同、劳务协议、保密、竞业限制）
F：知识产权授权许可协议
G：担保类文件（保证、抵押、质押、反担保）
H：债权债务处置类（债权转让、债务重组、和解协议）
I：委托居间代理协议
J：终止清算类（解除协议、终止协议、结算协议）

### 2.2 混合类型处理规则

#### 2.2.1 组合规则总则
1. **主类型决定访谈框架**：主类型完整执行整套访谈流程
2. **附属类型追加关键要素**：仅追加该类型专属的场景要素提问，不重复主类型已覆盖的通用要素
3. **数量限制**：主类型1个，附属类型最多2个（避免访谈过长导致转化率下降）
4. **冲突检测**：系统预置合法组合表，非法组合时主动提示用户调整

#### 2.2.2 合法组合规则表

| 主类型 | 合法附属类型 | 组合说明 | 特殊处理 |
|--------|-------------|---------|---------|
| A 买卖 | B 备忘录、G 担保 | 买卖为主，备忘录补充意向记录，担保追加保证条款 | 合并担保条款至合同正文 |
| A 买卖 | H 债权、I 居间 | 买卖为主，追加债权转让或居间佣金条款 | 分章节呈现 |
| B 备忘录 | A 买卖、C 投资、D 合作 | 备忘录为主，后续可能发展为正式合同 | 标注「意向性文件，不具强制约束力」 |
| C 股权转让 | D 合作、G 担保 | 股权交易为主，追加合作安排或股权质押 | 分别独立章节 |
| C 增资 | A 买卖、I 居间 | 增资为主，追加对赌条款或居间安排 | 对赌条款单独风险提示 |
| D 合作 | C 投资、F 知识产权 | 合作为主，追加投资条款或IP授权 | 分模块独立章节 |
| E 劳动 | F 知识产权、G 担保 | 劳动关系为主，追加竞业限制或保密条款 | 竞业条款单独风险提示 |
| F 知识产权 | G 担保、H 债权 | IP授权为主，追加质押或债权转让 | 质押条款需额外确认 |
| G 担保 | C 投资、H 债权 | 担保为主，关联主债权 | 必须确认主债权信息 |
| I 居间 | A 买卖、D 合作 | 居间为主，关联基础交易 | 佣金条款单独提示 |

#### 2.2.3 访谈问题去重机制
1. **通用要素提取**：系统从主类型提取通用要素（当事人、标的、价款、履行方式）
2. **专属要素追加**：附属类型只追加其专属要素
3. **重复检测**：如附属类型与主类型存在相同要素，跳过重复提问
4. **用户确认**：去重结果在访谈前展示给用户确认

#### 2.2.4 大纲合并规则
1. 主类型基础章节完整保留
2. 附属类型对应章节作为独立模块追加
3. 章节顺序：主类型章节 → 附属类型章节A → 附属类型章节B
4. 风险清单合并：主类型风险 + 附属类型专属风险

### 2.3 全局斜杠指令（后端优先拦截，不送入AI）

#### 2.3.1 `/重置`
- 清空当前项目全部会话状态
- 重置至初始化，开启全新访谈
- 访谈记录表、对话历史、大纲一并清空
- 不删除项目本身，仅重置状态

#### 2.3.2 `/回溯`（时光机模式）
**行为定义：**
1. 展示当前项目的完整历史快照列表
2. 用户可选择回退到任意历史节点
3. 回退后：
   - 访谈记录表恢复到该节点状态
   - 对话历史截断至该节点
   - 后续对话作废（可恢复）
4. 快照保存策略：
   - 每轮问答完成后自动生成快照
   - 快照保留最近20个，超过自动清理最早快照
   - 快照内容：确认要素、待确认要素、风险清单、大纲JSON

**注意事项：**
- 回溯操作不可逆，回退后的对话历史永久删除
- 回溯到 `outline_generated` 状态后，允许用户继续访谈或重新生成大纲

#### 2.3.3 `/导出`
- 打包输出标准化文档包：访谈记录表 + 文件框架大纲 + 风险清单 + 合同文本
- 前置校验：
  - 项目必须存在至少一条访谈信息
  - 合同文本必须已生成
- 导出格式：Word (.docx)、Markdown (.md)
- 匿名用户导出时触发登录提示
- 已登录用户触发付费流程

### 2.4 访谈记录表机制
每条项目持续持久化存储，每轮对话自动更新；包含三大模块：
- 已确认要素：双方达成一致的业务事实
- 待确认要素：尚未明确、后续需要补充的条件
- 风险提示：基于现有信息识别的法律风险

> 表格由后端结构化数据渲染，禁止由AI自由输出表格，防止格式错乱。

### 2.5 项目状态机（核心流转规则）
```
init（初始化）
    ↓ 用户选择主/附属文件类型
interviewing（访谈进行中）
    ↓ 持续问答采集业务信息，更新记录表
    ↓ 全部访谈问题完成
outline_generated（框架大纲已生成）
    ↓ 用户可继续补充信息 / 执行指令 / 生成完整合同文本
contract_generated（合同文本已生成）
    ↓ 用户可插入自定义内容、确认导出
ready_export（支持正式导出）
```

### 2.8 付费下载机制（V1.3修订）

#### 2.8.1 定价策略（支持后台动态调整）

**默认定价规则：**

| Token成本 | 用户支付金额 | 说明 |
|-----------|-------------|------|
| ≤ 2元 | 5.99元（固定价） | 简单合同，一口价 |
| > 2元 | 成本的2倍 | 复杂合同，按实际成本计费 |

**后台动态配置（V1.3新增）：**
- 管理员可在后台调整定价档位阈值
- 管理员可调整固定价格（默认5.99元）
- 管理员可调整倍数系数（默认2倍）
- 定价配置实时生效，无需重启服务

**配置示例：**
```json
{
  "pricing_config": {
    "fixed_threshold": 2.0,
    "fixed_price": 5.99,
    "multiplier": 2.0,
    "currency": "CNY"
  }
}
```

#### 2.8.2 支付流程
```
用户点击「下载合同」
    ↓
系统读取后台定价配置计算Token成本
    ↓
判断价格档位：
  - 成本≤阈值 → 固定价格
  - 成本>阈值 → 成本的倍数
    ↓
生成支付订单（显示金额、倒计时）
    ↓
展示支付二维码（微信/支付宝）
    ↓
用户扫码支付
    ↓
支付回调 → 更新订单状态
    ↓
解锁下载/复制权限
```

#### 2.8.3 支付状态机
```
pending（待支付）
    ↓ 用户扫码
paid（已支付）→ 解锁下载
    ↓
expired（已过期，30分钟）
    ↓ 超时未支付
cancelled（已取消）
```

#### 2.8.4 幂等性保障
- 同一订单ID重复请求支付回调，只处理一次
- 支付成功后自动解锁，无需用户再次操作
- 订单30分钟未支付自动过期，释放锁定

#### 2.8.5 支付渠道
| 终端 | 支付方式 |
|------|---------|
| Web网页端 | 微信二维码、支付宝二维码 |
| APP | 微信原生支付、支付宝原生支付 |
| 微信小程序 | 微信原生支付 |

#### 2.8.6 退款策略（V1.3新增）
- **退款由客服对接处理**
- 用户申请退款 → 客服审核 → 人工处理退款
- 系统记录退款申请和状态，便于追踪
- 退款成功后解锁的下载权限保持不变（防止滥用）

**退款申请流程：**
```
用户提交退款申请（理由、订单号）
    ↓
客服审核（1-3个工作日）
    ↓
审核通过 → 执行退款 → 通知用户
审核驳回 → 告知原因
```

### 2.9 AI合同文本生成（V1.0新增）

#### 2.9.1 触发条件
用户在 `contract_generated` 状态前执行 `/导出` 或点击「生成合同」按钮

#### 2.9.2 生成流程
1. 后端收集当前访谈快照（已确认要素、待确认要素、风险清单）
2. **用户可选插入自定义内容**（V1.3新增）
3. 调用AI服务生成合同文本
4. AI同时生成「风险提示」段落
5. 合同文本展示给用户预览

#### 2.9.3 风险标注要求
- 合同文本中高风险条款用 `⚠️` 标记
- 风险说明显示在合同末尾独立章节
- 必含免责声明：「本文档仅供参考，不构成法律意见，重大交易请咨询专业律师」

#### 2.9.4 Token成本控制
- 单份合同生成Token成本目标 ≤ 5元
- 策略：
  - 首屏大纲生成复用访谈上下文，减少重复输入
  - 合同文本分段生成，避免超长Prompt
  - 冷启动时预加载行业通用条款，减少生成长度

### 2.10 用户自定义内容插入（V1.3新增）

#### 2.10.1 功能概述
用户可在生成合同前，插入自定义表达内容到指定章节，使合同更符合个性化需求。

#### 2.10.2 插入方式

**方式一：章节级插入**
- 用户在大纲编辑页面，选择目标章节
- 点击「插入自定义内容」按钮
- 输入自定义文本内容
- 系统将该内容插入到指定章节位置

**方式二：自由插入**
- 用户可在合同文本编辑模式下，自由选择插入位置
- 输入自定义内容
- 系统自动标记为「用户自定义」，便于区分

**方式三：模板片段插入**
- 系统提供常用条款片段库（需达到1000次使用后启用）
- 用户可从片段库中选择插入

#### 2.10.3 数据结构
```json
{
  "custom_content_id": "uuid",
  "project_id": "uuid",
  "chapter_id": "uuid",
  "content_type": "custom/fragment",
  "content": "自定义条款内容...",
  "inserted_at": "2026-08-16T12:00:00Z",
  "inserted_by": "uuid"
}
```

#### 2.10.4 使用限制
- 每个项目最多插入10条自定义内容
- 自定义内容不影响AI生成的大纲结构
- 自定义内容不参与风险评估

#### 2.10.5 展示标识
- 自定义内容在合同中用 `【用户自定义】` 标识
- 导出文档中自定义内容与其他内容样式区分

### 2.11 合同模版沉淀机制（V1.3新增）

#### 2.11.1 触发条件
当系统累计使用次数达到**1000次**后，开始沉淀服务期合同数据并生成合同模板、条款模板。

#### 2.11.2 数据沉淀规则
- 统计周期：按自然月统计
- 数据来源：已完成导出且支付成功的订单
- 脱敏处理：移除当事人信息、敏感商业数据
- 存储位置：`contract_templates` 表（合同模板）、`clause_templates` 表（条款模板）

#### 2.11.3 模板生成机制
1. **合同模板**：
   - 基于高频交易场景（如买卖合同）
   - 聚合相似合同的章节结构
   - AI自动提炼最优条款表述
   - 管理员审核后入库

2. **条款模板**：
   - 从历史合同中提取高频条款
   - 按条款类型分类（违约责任、不可抗力、争议解决等）
   - 支持用户调用

#### 2.11.4 使用条件
- 模板功能在达到1000次后自动解锁
- 解锁前显示提示：「使用已达X次，即将开放模板库」
- 解锁后可选择「使用模板」快速生成合同

#### 2.11.5 后台管理
- 管理员可管理模板库（增删改查）
- 管理员可设置模板优先级
- 管理员可审核AI生成的模板

### 14.5 模板沉淀机制（V1.3新增）

#### 14.5.1 触发条件
当系统累计使用次数达到**1000次**后，开始沉淀服务期合同数据。

#### 14.5.2 数据收集规则
- 统计周期：按自然月统计
- 数据来源：已完成导出且支付成功的订单
- 脱敏处理：移除当事人信息、敏感商业数据
- 存储位置：`contract_templates`、`clause_templates`

#### 14.5.3 模板生成流程
```
达到1000次使用
    ↓
后台启动模板沉淀任务
    ↓
AI分析历史合同数据
    ↓
提炼合同模板结构
    ↓
提炼高频条款表述
    ↓
生成候选模板
    ↓
管理员审核
    ↓
审核通过 → 入库
审核驳回 → 删除候选
```

#### 14.5.4 使用限制
- 模板功能在达到1000次后自动解锁
- 解锁前显示提示：「使用已达X次，即将开放模板库」
- 模板使用不计入Token成本（复用已生成内容）
